# 店舗管理画面（ここっとベール）— モック統合版

もとは提案・要件確認のための**画面モック**だったが、現在は**実際の管理画面を兼ねる**。
単一の `index.html` だけで動き、外部のライブラリ・フォント・画像を一切読み込まない。

**表示**: `https://<ドメイン>/mock/`（管理 API と同じ Basic 認証の内側）。
`#resv` `#list` のように URL ハッシュで画面を直接開ける。旧 `/admin/` はここへリダイレクトされる。

## 2つの動作モード

起動時に管理 API（`/api/admin`）へ疎通確認し、届くかどうかでモードが決まる。

- **実運用モード**（本番サーバ経由で開いたとき）: ダッシュボード等に「実運用モード」の
  バッジが付く。予約管理（一覧・承認・来店登録・新規予約・メニュー・スタッフ登録）、
  顧客一覧・カルテ、テスト送信、SNS投稿は**実データで動き、操作は本番に反映される**。
  配信メッセージのテスト送信は、サーバ側で宛先が常にテスト用アカウントに固定される。
- **デモモード**（`index.html` を単体で開いたときなど API に届かないとき): 従来どおり
  `index.html` 内に直書きしたサンプルデータで動き、何を操作しても本番には影響しない。

デモモードの**サンプルデータに実在の顧客名や電話番号を書き込んではいけない**。画面共有・
スクリーンショットにそのまま乗る前提で扱う。なお実DBに同じサンプル顧客を投入して試したい
ときは `scripts/seed-customers.js` を使う。

**スタッフ情報・シフト入力**は実データで動く（Phase 8）。スタッフの追加・編集・LINE 連携・
グループ参加状況、公式LINE からのシフト変更申請・承認・本人への通知、**週次シフト表の入力**
（マスのクリックで保存、スタッフを追加すると行が増える）まで含む。

**実運用モードではサンプルの数字を出さない。** ダッシュボードの件数は実データに差し替わり、
売上・来店経路・トリマー実績のように**このシステムが持たない値はカードごと表示しない**
（「実運用モード」と表示された画面にサンプルの数字が並ぶと、実績と誤解されるため）。
ペットカルテのワクチンの欄、リマインドの初回フォロー状況カードも同じ理由で出さない。

リマインド設定は**店舗全体**と**お客様ごと**の2段階で、両方 ON のときだけ送られる。

- **店舗全体**（`/mock/#rem`）— 実装済みの4種（R1〜R4）を個別／一括で止める。
  未実装の4種は触れると誤解を招くため**状態表示（未実装）に置き換わる**
- **お客様ごと**（ペットカルテの「飼い主様へのリマインド設定」）— 種類ごとに止める。
  ジョブは飼い主様単位で送るため、**わんちゃんごとには分けられない**（同じ飼い主様の
  わんちゃんが複数いても送信は1通）。店舗全体で止めている種類は、お客様ごとに ON にしても
  送られないので、トグルではなく「店舗設定でOFF」と出す
- **全部まとめて止める**ときは、顧客一覧の「編集」にある**配信停止**（`opt_out`）

どちらも前々日確認は予約の確認連絡なので、OFF にするときだけ確認を挟む。

予約カレンダーは実運用モードでもサンプルのまま（構想）。
シフト表に入力した内容も予約カレンダーには反映されない。
**回数券・保育コースは実データで動く**（加入・付与・消化・失効。詳細は
[docs/plans.md](../../docs/plans.md)）。ワクチンの欄だけは実データが無いため表示されない。
ペットカルテは**わんちゃんの一覧（表）から始まる**。名前か「カルテ」を押すと開き、
「ペットカルテ」のパンくずで一覧へ戻る。いきなり特定の1頭が開くと、誰のカルテなのか
分からないまま操作されるため。列は わんちゃん・犬種/年齢・飼い主様・最終来店。

**顧客一覧は表**（飼い主様・わんちゃん・電話番号・LINE連携）。わんちゃんの名前を押すと
そのカルテが開く。**編集は行の直下を開いて行う**（画面を覆うモーダルは使わない）。
一覧を見ながら直せるうえ、どの行を編集しているのかが分かるため。保存しても一覧のまま。

**飼い主様の誕生日は画面から扱わない。** 誕生日メッセージ（R4）は `customers.birthday` を
見ており、この値はお客様ご自身の LINE 登録（LIFF）で入る。
顧客・ペット情報の編集は、顧客一覧・カルテの「編集」「＋ わんちゃん」ボタンから行う
（LINE グループの「会員情報」コマンドもこの画面 `/mock/#list` へ誘導される）。
顧客の**削除**は「飼い主様情報を編集」の中にある。わんちゃん・来店履歴・配信履歴も一緒に
消えて元に戻せないため、配信を止めたいだけなら「配信停止」を使う。

## 現行システムとの対応

リマインド画面の各行に付いているバッジが、実装状況をそのまま表している。

| バッジ | 意味 | 対応するジョブ |
|---|---|---|
| 実装済 | 現行システムで既に毎日動いている | R1 `preReminder` / R2 `afterVisit` / R3 `dormant` / R4 `birthday` |
| 構想 | まだ実装していない候補 | R5〜R8（初回後の追客・回数券・定額プラン・パッチテスト） |

**予約管理**画面の機能（承認・見送り、来店/取消/無断キャンセル、新規予約、
メニュー管理、スタッフの登録）はすべて実装済みで、実運用モードではこの画面が
そのまま本物の管理画面になる。

**テスト送信**は独立した画面（`/mock/#test`）にある。顧客へ送りうるメッセージは
**全種類**ここから確認できる。条件が揃うまで確認できない種類が残ると、文面を変えたときに
本番で初めて崩れに気付くことになるため。

| 送る対象 | 種類 |
|---|---|
| お客様を選ぶ | 休眠フォロー / 誕生日メッセージ |
| ご予約を選ぶ | 前々日確認 / 来店7日後フォロー / 予約リクエスト受付 / 予約の確定通知 / 予約の見送り通知 |

宛先はサーバ側で常に `TEST_LINE_USER_ID` に固定される。画面上部に現在の `SEND_MODE` を出す
（`dry_run` は送らずログに出すだけ、`live` は誤配信防止のため拒否する）。押してから
「届かない」を調べることにならないよう、押す前に分かる位置に置いている。
ご予約の期間は既定で**前後2週間**（過去の予約でも文面は確認できるため）。

**SNS投稿**のうち写真投稿（自動2分割・予約投稿）は実装済みで、実運用モードでは実際に
Instagram へ投稿される。**スレッズ**へも投稿できる（写真の左上のチェックで選んだ分だけ・
本文は別入力・20枚まで1投稿）。リール動画は構想。

予約カレンダーは現行システムには無い機能で、**構想**にあたる。
モックを見た人が「もう動いている」と誤解しやすい部分なので、説明時に必ず切り分けること。

## 画面の体裁

PC（1440px）とスマートフォン（390px）の両方で確認している。

- ブレークポイントは `860px`（サイドバー→横並びナビ、2カラム→1カラム）と
  `640px`（表をカードへ組み替え、入力欄を縦積み）の2つ
- **列の多い表**（予約一覧・シフト表・本日の自動リマインド）は、狭い画面で縮めると
  1文字ずつ折り返して読めなくなる。カードへ組み替えるか、`min-width` を与えて
  カード内で横スクロールさせるかのどちらかにする。
  カードへ組み替えるセレクタは**対象の表だけに限る**（`.rvtable` のようにクラスで絞る）。
  画面単位で指定すると、同じ画面にある料金表や店舗情報まで崩れる
- **一覧性が大事な表はカードに崩さず、横スクロールにする**。顧客一覧・ペットカルテの一覧
  （`.ctable`）は狭い画面でも表のままで、`min-width` を与えて `.tscroll` の中で横に流す。
  カードにすると1件あたりが縦に伸び、一度に見える件数が減って探しにくくなる。
  横スクロール中も誰の行か分かるよう、**飼い主様の列は `position:sticky`** で残す。
  行の直下に開く編集欄は、横に流れないよう画面幅に収めた入れ物（`.efit`）へ入れる
- **ボタンは狭い画面でも文字幅のまま**にする。全幅に伸ばすと画面が間延びし、
  一度に見える情報が減る。全幅にするのは入力欄だけ
- 期間の指定は日付を横に並べる。予約一覧（開始日・終了日・表示）は1行、シフト
  （ボタンが4つある）は日付の行とボタンの行の2行。1行に詰めると日付が読めない幅になる
- **`style="flex:…"` を HTML に直接書かない**。インライン指定は CSS より強く、
  狭い画面用の調整が効かなくなる（実際にシフトの日付欄がこれで崩れていた）
- シフト表は横スクロールしてもスタッフ名が分かるよう、**先頭列を `position:sticky` で固定**
- 期間指定の「開始日 〜 終了日」は、狭い画面では日付が縦に並ぶため「〜」を隠す
- 電話番号は保存値（ハイフン無し）のままではなく、画面ではハイフン区切りに整形する
- 説明文は**1〜2文**に収める。デモ用に書いた長い解説は、毎日使う画面では読み飛ばされて
  かえって操作の邪魔になる。手順や条件の詳細は `docs/` に置く

画面を追加・変更したときは、両方の幅で横スクロールが出ていないかを必ず確認すること。

## 画面が古いままのときの帯

デプロイしても、**開きっぱなしのタブは古い画面のまま**になることがある。`Cache-Control: no-cache`
を付けていても、タブ一覧から戻ったときに再検証せず描画する端末があるため（実際に
「直したはずが反映されていない」と何度か誤解された）。

いま読み込んでいる HTML の `Last-Modified` と、サーバ上のファイルの更新時刻
（`GET /api/admin/mock-version`）を突き合わせ、古ければ画面上部に帯を出して再読み込みを促す。
判定は**読み込み時**と**タブに戻ったとき**（`visibilitychange`）に行う。
判定できないときは何も出さない（誤検知で毎回帯が出る方が害が大きいため）。

## 別の店舗・業種へ流用する

**店名・ロゴ・サブタイトル・営業時間・定休日・住所・電話は `.env`（`STORE_*`）で変わる。**
実運用モードで起動時に `/api/admin/store` を読み、画面に反映する。ここを直しに
`index.html` を触る必要はない。手順は [docs/new-store.md](../../docs/new-store.md)。

`index.html` の編集が要るのは配色・料金表・サンプルデータの3つ。

配色は先頭の `:root` にある CSS 変数だけで決まる。ダークモードを含めて4ブロックあるので、
同じ変数を4箇所とも書き換える。

| 変数 | 役割 |
|---|---|
| `--bg` / `--surface` | 背景 / カード面 |
| `--ink` / `--muted` | 文字 / 補助文字 |
| `--accent` | メインカラー（ボタン・選択状態） |
| `--honey` | サブカラー（強調バッジ） |
| `--good` / `--warn` / `--crit` | 状態色（良好 / 注意 / 警告） |
| `--side` | サイドバー（ブランド面） |

サンプルデータは `FAMILIES` / `RESV` / `MENUS` / `WEEK` / `MONTH` / `TRIALS` の6つの配列に
集約してある（デモモード専用。実運用モードでは使われない）。

業種が変わるときは、色より**用語の置換**が仕上がりを左右する。置換対象は画面ごとに洗い出して
から着手すること。1箇所でも残ると一気に借り物に見える。

## 公式サイトとの対応

コース構成と料金は [cocotte-vert.me](https://cocotte-vert.me/) の掲載内容に合わせている。

| モック上の表記 | 出典 |
|---|---|
| シャンプーコース / シャンプー＆カットコース | トリミングのコース。**料金は犬種ごとに異なる**ため、予約フォームには金額を出さない |
| 宿泊（レギュラーコース / 保育コース） | 1泊2日 3,850円 / 4,950円。4泊目以降10%OFF、2頭同室は2頭目半額（中型ゲージのみ） |
| 一時預かり | 550円・対応時間 10:00〜19:00 |
| ワンず写メ日記 | 1日2通 330円のオプション（写真or動画はおまかせ） |

営業時間 10:00〜19:00・**木曜定休**（祝日の場合は営業）は公式サイトの記載どおり。
定休日は `MONTH` 配列（0 の日）・`WEEK` 配列の `closed`・シフト表の見出しの3箇所に散っているため、
変更するときは3箇所とも直す。なお**定休日でもお預かり（ホテル）の受付は 10:00〜17:00 で行われる**ため、
カレンダー上は定休でもホテル行だけは動く日がありうる（モックでは簡略化して全休で表現している）。

料金表は公式サイトの掲載順に**全29犬種**を載せている。「—」は取り扱いなし（シャンプーのみ）。
ミックス犬・その他の犬種は、近いサイズ・毛量の犬種の料金になる旨を注記している。
料金が変わったときは公式サイトを正とし、掲載がない犬種を推測で埋めないこと。
