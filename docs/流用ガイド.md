# 外観・機能を他アプリへ流用するためのガイド

対象: `docs/osaka-kitaku/mock/index.html`（モック v1.3.1）
このモックは「デザイントークン（CSS変数）＋汎用部品」の構成で作られており、
**業種の異なるアプリにも配色・文言の差し替えだけで転用できます**。

---

## 1. 外観の流用 — テーマは変数8個で決まる

配色はすべてファイル冒頭の `:root` のCSS変数で管理されています。
ここを差し替えるだけで全画面の見た目が一括で変わります（ダークモードも同様に4ブロック）。

| 変数 | 役割 | FREEWANでの値 |
|---|---|---|
| `--bg` / `--surface` | 背景 / カード面 | アイボリー / 白 |
| `--ink` / `--muted` | 文字 / 補助文字 | 濃茶 / グレージュ |
| `--accent` | メインカラー（ボタン・選択状態） | 深緑 `#33695B` |
| `--honey` | サブカラー（強調バッジ） | ハニーゴールド |
| `--good` / `--warn` / `--crit` | 状態色（良好/注意/警告） | 緑 / 琥珀 / 赤 |
| `--side` | サイドバー | 深緑（ブランド面） |

例: 美容室なら `--accent` をネイビーに、`--side` を黒に変えるだけで印象が変わる。
ロゴ・店名はサイドバーの `.brand` ブロック1箇所。

## 3. 流用の進め方（3パターン）

### A. モックの流用（提案・要件定義用）
別案件の商談用に、このHTMLをコピーして配色・店名・サンプルデータを差し替える。
**半日程度**で「その会社専用に見えるモック」が作れる。要件のヒアリング効率が大きく上がる。

### B. テンプレート化（複数案件で使う場合・推奨）
色・店名・メニュー構成・機能ON/OFFを設定ファイル（JSON）に外出しし、
「設定を書けば新しいモックが生成される」形に整理する。
FREEWANの系列5店舗展開もこの仕組みに乗る（店舗ごとに設定だけ変える）。

### C. 本システムの共通基盤化（実開発時）
実装時にUI部品と機能モジュールを共通ライブラリとして切り出し、
FREEWAN本体も他アプリも同じ基盤の上に作る。保守が一本化される代わりに初期設計が重くなる。
2案件目が具体化した時点で判断するのが良い。

## 4. 権利・注意点

- 本モックはこのリポジトリ内で新規に作成したコードのみで構成（外部ライブラリ・フォント・画像の読み込みなし）。**流用にライセンス上の制約はありません**
- FREEWAN固有の文言・データ（店名・スタッフ名・顧客サンプル）は流用先で必ず差し替えること
- 業種が変わる場合、色だけでなく**用語**の置換が品質を左右する（「カルテ」→「施術記録」、「入園」→「入会」等）。置換対象の用語は画面ごとに洗い出してから作業する

## 5. 次のステップ

流用先のアプリ（業種・画面イメージ・使いたい機能）が決まったら、
上記A〜Cのどれで進めるかを決めて着手する。Aなら即日〜半日で初版が出せる。
