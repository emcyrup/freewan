# 回数券・保育コース（定額プラン）

わんちゃんごとの回数を管理する。ペットカルテから加入・付与・消化ができる。

## 考え方

**残回数を列で持たず、付与・消化・失効を1行ずつ積んだ元帳（`plan_credits`）の合計から導く。**
集計値を別に持つと履歴と残数がずれ、どちらが正しいのか分からなくなるため。

```
付与  +4  2026-07-01（期限 2026-08-31）
消化  -1  2026-07-05
消化  -1  2026-07-12
                     → 残り 2 回
```

種類は2つ。

| | 何か | 付与のしかた |
|---|---|---|
| `plan` | 保育コースなどの定額プラン | 毎月1日に自動付与（加入時はその場で当月分） |
| `ticket` | 回数券（都度購入） | カルテから手で付与 |

## 消化する順番

店舗の運用に合わせてあり、変えるときは `src/plans/service.js` の `CONSUME_ORDER` だけを直す。

- **保育コース** — **当月分を先に**消化し、繰越分は後回し。結果として繰越分の方が失効しやすいが、
  それを承知の運用（画面にも同じ説明を出している）
- **回数券** — 期限の近いものから消化する（失効を減らすため）

期限切れの付与は消化の対象にしない。残りが足りないときは**足りるぶんだけ消化**し、
不足を返す（足りないから何もしない、にすると来店の記録が残らなくなるため）。

## 繰越と失効

プランの `carry_over_months` が繰越できる月数。`1` なら翌月末まで、`0` なら当月末で切れる。

失効は**毎日 0:45 JST** に確認し、期限を過ぎた残りを負の行として積む。
消化と同じ元帳に入るので、残数と履歴がずれない。失効の履歴はカルテの「失効した回数」に出る。

## 月次付与

**毎月1日 0:30 JST**、加入中のわんちゃん全員に `monthly_quota` を付ける。

- 二重付与は部分ユニーク索引（`plan_credits_monthly_uniq`）で防いでいる。**何度実行しても増えない**
- **月の途中で加入しても当月分は満額**（日割りしない）。翌月まで0回のままだと、加入したのに使えないため
- 解約しても**残っている回数は期限まで使える**（加入だけが終わる）

サーバーが落ちていた・デプロイが月初を跨いだ、といったときは手で埋められる。

```bash
docker compose exec app node scripts/run-plan-job.js --job=grant    # 当月分の付与
docker compose exec app node scripts/run-plan-job.js --job=expire   # 期限切れの失効
```

## 画面

ペットカルテに3つのカードが出る（実運用モードのみ）。

| カード | 内容 | 操作 |
|---|---|---|
| 保育コース | 当月分の消化状況・繰越分と期限 | 加入 / 1回 消化 / 解約 |
| 回数券 | 残回数と次の期限 | 回数券を追加 / 1回 消化 |
| 失効した回数 | 失効の履歴と累計 | — |

コースのマスタは `plans` テーブル。立ち上げ時は `node scripts/seed-plans.js` で
「保育コース 月4回 / 月8回」が入る。

## API

| | |
|---|---|
| `GET /api/admin/plans` | コースのマスタ（`?all=1` で停止中も） |
| `POST/PATCH /api/admin/plans[/:id]` | マスタの追加・変更 |
| `GET /api/admin/pets/:id/credits` | 残回数・当月の利用状況・失効履歴 |
| `POST/DELETE /api/admin/pets/:id/plan` | 加入・解約 |
| `POST /api/admin/pets/:id/credits` | 回数券の付与 |
| `POST /api/admin/pets/:id/credits/use` | 消化 |

## まだ無いもの

- **来店登録との連動**。いまは消化を手で押す。自動で引くには予約に「どの子か」を持たせる必要があり、
  `reservations` に `pet_id` を足す作業が要る（予約フォーム・取り込み API にも波及する）
- **R6 / R7 の配信**（回数券・保育コースの残回数のご案内）。残回数が取れるようになったので、
  次はこれを送る条件を組む
- **ダッシュボードの入園数**。加入者数・当月の利用回数から出せるようになった

## 確認していただきたい運用ルール

実装は現行モックの表示に合わせているが、店舗ごとに違いうる。北区店のヒアリングで確認したい。

- 消化の順番（当月分優先でよいか）
- 繰越の月数（1ヶ月でよいか）
- 月途中で加入したときの当月分（満額でよいか、日割りか）
- 解約したときの残回数（期限まで使えるままでよいか）
