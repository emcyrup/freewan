# モックを実システムにするために必要な項目

対象: FREEWAN大阪北区店 ペットサロン＆スクール管理システム（モック v1.3 時点の機能）
用途: 7/30打ち合わせ・見積もり・開発準備のチェックリスト

---

## 1. 店舗側でご準備いただくもの

### アカウント・外部サービス

| 項目 | 必要な作業 | 備考 |
|---|---|---|
| **LINE公式アカウント** | Messaging API の有効化、チャネル情報の共有 | リマインド送信・シフト申請botの土台。応答モードが「チャットのみ」の場合は設定変更が必要 |
| LINEの配信プラン | 月間送信数に応じたプラン確認 | リマインド8種×顧客数で無料枠(月200通)は確実に超過。概算: 月1,000〜5,000通 → 有料プラン（月5千円前後〜）を想定。7/30に顧客数から試算 |
| **Instagram** | ビジネスアカウント化 ＋ Facebookページ連携 | 自動投稿（2分割・リール）のAPI利用に必須 |
| **EPARK** | 予約通知メールの受信アドレス確認・メールのサンプル提供 | 通知メールの自動取り込みに使用。転送設定ができるかも確認 |
| **Airレジ** | 売上CSVのエクスポート手順の確認 | トリマー貢献売上・ダッシュボード集計に使用 |
| ドメイン（任意） | 例: system.freewan.jp のような管理画面URL | なければこちらで用意も可 |

### データ・情報

- 現行スプレッドシート一式（**移行元データ**）
  - サロンカルテ / スクール記録 / ワクチン管理表 / 回数券管理
- 店舗マスタ情報
  - 営業時間（モックでは 7:00〜22:00・通常営業 9:00〜18:00 と仮置き）/ 定休日（水曜と仮置き）
  - スタッフ一覧（氏名・役割・新人か・LINEアカウント）
  - メニュー・料金表 / 会員プラン規定（月4・月8）/ 回数券規定（回数・期限の起算日）
- リマインド文面の確定（R1〜R8それぞれ。モックの文言をたたき台に）
- 個人情報の取り扱い方針（プライバシーポリシー、LINE連携の同意の取り方）

## 2. 開発項目（こちらで構築するもの）

### アプリケーション

| # | 項目 | モックの対応画面 |
|---|---|---|
| 1 | 認証・権限管理（店長/スタッフ/トリマー別の画面・操作制限） | 全画面 |
| 2 | 顧客・ペットDB（飼い主単位、複数頭、来店経路、LINE連携状態） | 顧客一覧・カルテ |
| 3 | カルテ・来店履歴（Googleフォーム入力の取り込み or 置き換え） | 顧客カルテ |
| 4 | ワクチン管理（期限計算・対象者抽出「直近半年以内の利用者」） | 顧客カルテ |
| 5 | 予約管理（日/週/月、ドラッグコピー、リサイズ、キャンセル/削除、新規+30分枠、時間帯色分け） | 予約カレンダー |
| 6 | シフト管理（選択式入力、カレンダー反映、新人⭐、LINE申請→承認フロー） | シフト入力 |
| 7 | 会員・回数券エンジン（残回数、当月優先→振替消化、失効の顧客別記録） | カルテ・ダッシュボード |
| 8 | リマインドエンジン（R1〜R8の条件判定、店舗設定×顧客別設定、送信キュー、スタッフ確認モード） | リマインド |
| 9 | 通知基盤（顧客: LINE/メール自動振り分け、スタッフ: LINE・メール） | 全体 |
| 10 | EPARKメール自動取り込み（パーサ、取り込み失敗時のアラート） | 予約カレンダー |
| 11 | ダッシュボード（KPI、体験入園一覧、トリマー実績、来店経路、検索） | ダッシュボード |
| 12 | SNS投稿（10枚超の自動2分割、リール、予約投稿） | SNS投稿 |
| 13 | LINE bot（顧客/スタッフの判別、シフト申請の解釈、既存の自動応答との共存） | シフト入力 |

### インフラ・非機能

- サーバー/ホスティング（クラウド）、SSL、独自ドメイン設定
- データベースと**日次バックアップ**
- 監視・エラー通知（EPARK取込失敗、LINE送信失敗などをスタッフへ通知）
- **マルチ店舗対応の設計**（系列5店舗展開を見据え、店舗IDでデータ分離）
- スマホ・タブレット対応（モックと同様のレスポンシブ）
- 操作ログ（誰がいつ予約を変更・削除したか）

## 3. 運用として決めること（7/30に確認したい）

1. リマインド送信の**時間帯**と、送信前に**スタッフ確認を挟むか**（全自動か）
2. 誕生日メッセージの対象（犬・飼い主・両方）
3. 時間帯色分けの基準時刻（モックは 9:00 / 18:00 で仮置き）と早朝・夜間の料金有無
4. 新規顧客+30分枠のルール確定（全メニュー対象か、カットのみ か等）
5. シフト申請の承認者（店長のみか）と、承認なし反映を許すケース
6. LINE未連携顧客への送信手段（メールで良いか、電話リストに載せるか）
7. 削除と「キャンセル記録」の使い分けルール（キャンセル率を集計に使うか）
8. Googleフォーム（現行カルテ入力）を残すか、システムのフォームに置き換えるか
9. 管理画面を使う端末（店のPC/タブレット/個人スマホ）とアカウント数

## 4. 概算の目安

| 項目 | 目安 |
|---|---|
| 開発期間 | 約3〜4ヶ月（8月要件確定 → 11月本稼働。導入プロセス.md参照） |
| ランニング費用 | サーバー: 月数千円〜1万円程度 ＋ LINE配信プラン（送信数次第で月0〜1.5万円程度） ＋ ドメイン年数千円 |
| 外部APIの費用 | Instagram API・LINE Messaging API 自体は無料（LINEは配信通数課金のみ） |
| 5店舗展開時 | 店舗追加は「設定＋データ移行」で対応できる設計とする（開発やり直し不要） |

※開発費用は要件確定後にお見積もり。モックで画面仕様がほぼ固まっているため、ブレは小さい想定。

## 5. 構築の進め方（再掲・要約）
