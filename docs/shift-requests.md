# スタッフ勤怠（シフト変更申請）

スタッフが公式LINE のトークへ**自由な文章**でシフトの希望を送ると、申請として店長に届く。
店長が店舗管理画面で承認・却下すると、結果が申請したスタッフへ LINE で自動通知される。

```
スタッフ（LINE）              システム                    店長（店舗管理画面）
  「8/1 有休お願いします」 →  Haiku で解釈 → 申請を登録  →  スタッフ情報・シフト画面に表示
                          ←  「受け付けました」を返信
                                                            承認 / 却下 を押す
  「承認されました」      ←  結果を Push で通知        ←
```

## スタッフ情報の画面

`/mock/#shift`（**スタッフ情報・シフト入力**）にスタッフの一覧がある。

- スタッフの**追加**、**編集**（名前・在職/退職・LINE ID）
- **LINE連携済み / 未連携**の表示
- **スタッフ用LINEグループへの参加状況**（参加中 / 未参加 / 不明）
- 連携コードの発行

「退職」にすると予約フォームや新規予約の担当候補から外れる。シフト表からも外れるが、
過去の予約には名前が残る。

**削除**は「編集」の中にある。シフトの入力内容と、LINE から届いた申請の履歴も一緒に消える。
**予約の担当として登録がある場合は削除できない**（履歴が壊れるため）。その場合は退職を使う。

グループ参加の判定は、スタッフ通知先の LINE グループが設定済みで、かつそのスタッフが LINE 連携済みの
場合のみ行える。判定できないときは「不明」と出し、未参加とは言い切らない。

## スタッフを LINE に連携する（最初に1回だけ）

連携の方法は3通り。いずれか1つでよい。

### ① スタッフ用LINEグループで名前を送る（いちばん簡単）

スタッフ本人が、**スタッフ用のLINEグループ**で `スタッフ登録 高橋` と自分の名前を送る。
発行済みの連携コードを送っても同じように連携できる。
bot が「高橋さんのLINEアカウントを連携しました」と返せば完了。

- 使えるのは**スタッフ通知先に設定済みのグループだけ**。設定されているかどうかは
  `/mock/#shift` の「公式LINE botからの申請」カードに
  「スタッフ用グループ 設定済み / 未設定」として表示される。未設定なら②か③を使う
  （グループを設定するには、Bot をスタッフ用のLINEグループに招待する）
- 店舗管理画面に登録された名前と一致する必要がある（姓名の間の空白は無視する）
- **同名のスタッフが複数いる場合は連携しない**。別人に紐付くと誤った相手へ通知が飛ぶため、
  その場合は画面から LINE ID を直接設定する

### ② 連携コードを発行して送る

1. `/mock/#shift` でそのスタッフの **「連携コード発行」** を押す（6桁・**有効期限24時間**）
2. スタッフ本人が **`123456` と数字だけ送る**（`スタッフ登録 123456` でもよい）。
   **1:1 のトークでも、スタッフ用グループでもどちらでもよい**

コードは使い捨てで、連携すると無効になる。機種変更などでやり直したいときは「コード再発行」を押す。

送り方の細かな違いは吸収する。接頭辞の有無、区切りの空白の有無、全角空白、`:`、
**全角数字**（`１２３４５６`）、`スタッフ連携` / `シフト登録` という言い方のどれでも受け付ける。

**数字だけの発言は、発行済みで期限内のコードに一致したときだけ連携に使う。** 一致しなければ
何も起きなかったものとして通常どおり処理するため、顧客がたまたま6桁の数字を送っても
会話を横取りしない。

**1:1 で名前を送っても連携しない。** 名前を知っているだけで誰でもそのスタッフに成りすませて
しまうため、名前での連携はスタッフ用グループ限定にしている（1:1 では送り方を案内して終わる）。

### ③ 画面から LINE ID を直接入力する

LINE の userId が分かっている場合は、「編集」から直接入力できる（`U` で始まる33文字）。
形式が違う場合と、他のスタッフに設定済みの ID は保存できない。
空にすると連携を解除する。

## 申請の書き方

日付と区分が読み取れれば、文章の形は自由。

| 送る文の例 | 解釈される内容 |
|---|---|
| `8/1 有休お願いします。子どもの行事のため` | 8/1 有休（理由つき） |
| `7/31 10時から12時まで時間休もらえますか` | 7/31 時間休 10:00〜12:00 |
| `明日は公休にしてください` | 翌日 公休 |
| `8/1と8/2 休みます` | 2件の申請に分かれる |

区分は **出勤 / AM半休 / PM半休 / 公休 / 有休 / 時間休** の6種類。

**読み取れないときは申請を作らない。** 半休の午前・午後が書かれていない、時間休の時刻が
片方しかない、日付が特定できない、といった場合は「読み取れませんでした」と返信して書き直しを促す。
誤った勤怠が承認まで通る方が害が大きいため、迷ったら申請にしない設計にしている。

同じ日について承認待ちが残っている状態で送り直すと、**新しい内容で上書き**される
（承認済みの履歴には手を付けない）。

## シフト入力

`/mock/#shift` の「シフト入力」が週次のシフト表。**スタッフを追加すると、この表に行が自動で増える**
（退職にすると外れる）。マスをクリックすると

```
出勤 → AM半休 → PM半休 → 公休 → 有休 → 時間休 → 未入力 → 出勤 …
```

の順に切り替わり、**その都度保存される**。時間休を選んだときだけ開始・終了の時刻を尋ねる。

- 表示する期間は日付で指定できる（**最大31日**。超える指定は切り詰める）。
  「前へ / 次へ」は表示中の日数ぶん動き、「今週」は月〜日に戻す
- **未入力（—）は「出勤」ではない**。入力漏れの日に予約を入れてしまわないよう、
  入っていないことを区別している
- 木曜（定休）も見出しに出るが、入力自体は妨げない（お預かりの受付があるため）

予約カレンダーへの反映はまだ（構想）。

## 承認する

`/mock/#shift` の「承認待ちの申請」に一覧される。各行には解釈結果に加えて**申請の原文**を出しているので、
AI の読み違いがないか確認してから承認する。

**承認すると、シフト表の該当のマスにも反映される。**

承認・却下のどちらでも本人へ LINE が飛ぶ。トーストに送信結果が出る。

| 表示 | 意味 |
|---|---|
| 本人へLINEで通知しました | 送信済み |
| dry_run のためLINE通知は送っていません | `SEND_MODE=dry_run`。動作確認中はこれが正常 |
| LINE未連携のため通知できませんでした | そのスタッフがまだ連携していない |
| LINE通知に失敗しました | LINE API 側のエラー。Slack にも通知される |

## 連携できないときの切り分け

**`スタッフ登録 …` で始まる発言には必ず何かを返す**設計にしている。無反応なら、その発言が
そもそも Bot に届いていない（後述）。返信の内容で原因が分かる。

| 返ってきた内容 | 原因と対処 |
|---|---|
| 「〇〇さんのLINEアカウントを連携しました」 | 成功 |
| 「連携コードを確認できませんでした」 | コードが違うか、24時間の期限切れ。画面から再発行する |
| 「〇〇というスタッフが見つかりません」 | 店舗管理画面に登録された名前と一致していない |
| 「スタッフ通知先のLINEグループがまだ設定されていません」 | Bot をスタッフ用グループに招待するか、1:1 でコードを送る |
| 「このグループはスタッフ通知先として設定されていません」 | 別のグループで送っている。スタッフ用グループか 1:1 で送る |
| 「送信された方のLINEアカウントを特定できませんでした」 | グループ発言から送信者を識別できない。1:1 でコードを送る |
| 「このトークでは6桁の連携コードで登録できます」 | 1:1 で名前を送っている。コードを送る |
| **「ご連絡ありがとうございます。内容を確認し、担当者よりご連絡いたします」** | 顧客向けの応答。連携コマンドとして認識されていない。コードが期限切れか、発行済みのものと違う。画面から再発行して送り直す |
| **何も返ってこない** | Bot に発言が届いていない。LINE 公式アカウントの**応答モードが「チャット」**になっていないか、**Webhook が有効**かを LINE Official Account Manager で確認する |

サーバのログには `[staff-link] source=... by=... ok=...` が出る（LINE userId は残さない）。

## 顧客の発言と混ざらないか

混ざらない。申請として解釈するのは次の条件をすべて満たす発言だけ。

- 1:1 のトーク（グループでの雑談は対象外）
- 送信者の LINE userId が、連携済みスタッフとして登録済み

未連携の相手の発言は、これまでどおり顧客からのメッセージとして処理される（電話番号の突合、
来店フォローへの返信の分類）。連携コマンドだけは未連携でも受け付けるが、`スタッフ登録` の
接頭辞を必須にしているため、顧客が6桁の数字を送っても反応しない。
